2️⃣ 内存管理对比

方面 Go Rust C++
管理方式 GC（自动回收） 所有权 & 借用 + 生命周期 手动 delete / new 或智能指针
悬挂指针 基本不会 编译器保证不会 很容易出现
内存泄漏 GC 避免大部分 编译器保证 RAII（几乎不会） 可能出现，需手动管理
性能影响 GC 停顿可能影响延迟 无 GC，性能可控 高性能，但需小心内存管理

3️⃣ 并发对比

语言 并发模型 优缺点
Go Goroutines + Channels 轻量级、易用、调度由 runtime 管理；可能 GC 暂停影响延迟
Rust async/await + Send/Sync 安全、零成本抽象，但需要掌握生命周期和 trait，学习曲线高
C++ std::thread / Boost / 原生线程 高度可控，性能最好，但容易出现死锁、数据竞争，需要手动管理同步

4️⃣ 安全性

安全性方面 Go Rust C++
类型安全 是 是 是
内存安全 依赖 GC 编译期保证 依赖开发者
并发安全 简单但不严格 编译期借用检查保证 开发者自己保证
越界访问 runtime panic 编译器 & borrow checker 阻止 可能出现 UB

5️⃣ 性能比较
C++：原生指针 + 零开销抽象 → 最快
Rust：接近 C++，无 GC，优化非常强
Go：有 GC，但 Goroutine 调度极快，适合网络/IO密集型

6️⃣ 泛型与抽象

语言 泛型 / 模板 特点
Go 1.18+ 泛型 类型安全，但语法简单
Rust trait + 泛型 零开销抽象，函数和类型都可以泛型化
C++ template 功能强大，但错误信息复杂，模板元编程复杂

7️⃣ 应用场景

语言 常见应用
Go 云服务、微服务、网络服务、CLI 工具
Rust 系统编程、嵌入式、WebAssembly、区块链、性能关键库
C++ 系统底层、游戏开发、图形渲染、高性能计算

🔹 总结建议

  1. 想快速上手、开发网络/服务端应用 → Go
  2. 想追求内存安全、零成本抽象、系统级开发 → Rust
  3. 极致性能、硬件控制、游戏或图形开发 → C++

Shell

2026-09-13 Linux
  • bash - UNIX shell 目的是作为 Bourne Shell (sh) 的免费软件替代品 (Bash 是 Linus Torvalds（Linux 的创建者）移植到 Linux 的首批程序之一)
  • Z shell - 一个与 Bash 非常相似的 UNIX shell,Zsh 是 Bourne shell 的扩展
  • Fish Shell - 一个强调交互性和可用性的 UNIX shell 环境,与 Zsh 不同，Fish 旨在为用户提供交互性，而不是信任用户实现自己的配置

Bash、Z Shell 和 Fish Shell 各有优点，也有一些相似之处。既然对它们有了更多的了解，你就可以在工作中更有效地使用它们。
如果你想要更可配置的 shell，你可以使用 Zsh（甚至安装 Oh My Zsh）。如果你想要更多交互的终端体验，同时不需要大量配置，你可以使用 Fish Shell。如果你想要经典的感觉，你可以保留 Bash。

MacOS 可能禁用了 cron，可以用 launchd 代替：

launchd 是 MacOS 用来管理系统和用户级别的守护进程的工具

  • LaunchDaemons（后台服务）

    • 适用于系统级别的任务，通常以 root 权限运行。
    • 在 开机时 启动，不依赖用户登录。
    • 目录：/System/Library/LaunchDaemons/ 和 /Library/LaunchDaemons/
    • 适用于系统服务，如数据库、守护进程等。

  • LaunchAgents（用户任务）

    • 适用于用户级别的任务，以当前用户权限运行。
    • 在 用户登录后 才会启动。
    • 目录：/System/Library/LaunchAgents/、/Library/LaunchAgents/、~/Library/LaunchAgents/
    • 适用于个人任务，如开机自动运行应用、定时脚本等。

什么时候用 LaunchDaemons？

  1. 你希望一个进程开机自动运行，而不依赖用户是否登录。
  2. 任务需要root 权限（比如修改系统文件）。

什么时候用 LaunchAgents？

  1. 任务需要在用户登录后运行，比如启动应用、挂载网络驱动等。
  2. 你不需要 root 权限，而是以当前用户权限运行。
