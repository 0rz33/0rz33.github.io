VIM

2026-09-19 Linux

Vi编辑器是所有Unix及Linux系统下标准的编辑器，

vi和vim都是Linux中的编辑器，不同的是，vim比较高级，可以视为vi的升级版本。vi使用于文本编辑，但是vim更适用于coding（写代码的）。

Vim重点是光标的移动，模式切换，删除，查找，替换，复制，粘贴，撤销命令的使用。

三种模式

  • 命令模式：在该模式下是不能对文件直接编辑，可以输入快捷键进行一些操作（删除行，复制行，移动光标，粘贴等等）【打开文件之后默认进入的模式】；
  • 编辑模式：在该模式下可以对文件的内容进行编辑；
  • 末行模式：可以在末行输入命令来对文件进行操作（搜索、替换、保存、退出、撤销、高亮等等）；

命令模式

光标移动

  • 行首 按键shift + 6 或 ^
  • 行尾 按键shift + 4 或 $
  • 首行 gg
  • 末行 G
  • 翻屏
    • 向上翻屏 按键ctrl + b （before） 或 PgUp
    • 向下翻屏 按键ctrl + f （after） 或 PgDn

复制操作

  • 所在行 yy
  • 粘贴：在想要粘贴的地方按下p键

剪切/删除

  • 剪切/删除光标所在行 dd
  • 剪切/删除光标所在的当前行之后的内容，但是删除之后下一行不上移 D

撤销/恢复

  • 撤销 u （undo）
  • 撤销5个改变 :undo 5
  • 你的撤销历史 :undolist
  • 重做最后的改动 按键ctrl + r:
  • 取消当前行中所有的改动 U:
  • 回到4分钟前 :earlier 4m
  • 前进55秒 :later 55s

替换

r: 替换光标处的字符，同样支持汉字。
R: 进入替换模式，按esc回到正常模式。

末行模式

进入方式：由命令模式进入，按下:或者/（表示查找）即可进入
退出方式：

  1. 按下按键esc
  2. 连按2次按键esc键
  3. 删除末行全部输入字符
  • 保存文件:w
  • 另存为:w 路径
  • 退出文件:q
  • 保存并且退出:wq
  • 表示强制退出，刚才做的修改操作不做保存:q!
  • :!外部命令
  • /关键词 搜索查找
  • 替换 -> %表示整个文件 g表示全局（global）
    • :s/搜索的关键词/新的内容 (替换光标所在行的第一处符合条件的内容)
    • :s/搜索的关键词/新的内容/g (替换光标所在行的全部符合条件的内容)
    • :%s/搜索的关键词/新的内容 (替换整个文档中每行第一个符合条件的内容)
    • :%s/搜索的关键词/新的内容/g (替换整个文档的符合条件的内容)
  • 显示行号（临时）
    • :set nu[number]
    • :set nonu
  • 文件多开:files
    • 果需要指定切换文件的名称，则可以输入:open 已经打开的文件名
    • “:bn”切换到下一个文件（back next）
    • “:bp”切换到上一个文件（back prev）
分屏功能

  • 分屏

    • 水平方向分屏打开新文件 横向切分 :sp文件名 :split文件名
    • 垂直方向分屏打开新文件 竖向切分 :vsp文件名 :vsplit文件名
    • 上下分割当前打开的文件 按键Ctrl+w s
    • 左右分割当前打开的文件 按键Ctrl+w v

  • 关闭分屏

    • 关闭当前窗口按键Ctrl+w c
    • 关闭当前窗口，如果只剩最后一个了，则退出Vim按键Ctrl+w q

  • 移动光标

    • 把光标移到右边的屏 按键Ctrl+w l
    • 把光标移到左边的屏中 按键Ctrl+w h
    • 把光标移到上边的屏中 按键Ctrl+w k
    • 把光标移到下边的屏中 按键Ctrl+w j
    • 把光标移到下一个的屏中 按键Ctrl+w w

  • 移动分屏

    • 向右移动 按键Ctrl+w L
    • 向左移动 按键Ctrl+w H
    • 向上移动 按键Ctrl+w K
    • 向下移动 按键Ctrl+w J

  • 屏幕尺寸

    • 让所有的屏都有一样的高度 按键Ctrl+w =
    • 增加高度 按键Ctrl+w +
    • 减少高度 按键Ctrl+w -

k6

k6 是一个压力测试套件，使用 golang 编写。主要特性有：

  • 提供了友好的 CLI 工具
  • 使用 JavaScript 代码编写测试用例
  • 可以根据性能条件设置阈值，表明成功还是失败

k6 没有使用 nodejs 而是 golang 程序，通过包裹了一个 JavaScript 运行时来运行 JavaScript 脚本，因此不能直接使用 npm 包以及 Nodejs 提供的一些 API。

同时，k6 在运行测试时，没有启动浏览器，主要用于测试页面以及 API 加载速度。k6 提供了通过网络请求（HAR）生成测试脚本的方法，实现更简便的测试脚本编写，以及 session 的维护。

系统对比 Go (Golang)、Rust 和 C++

1️⃣ 语言概览

语言 Go (Golang) Rust C++
发布年份 2009 2015 1985
设计目标 简单、高效、并发友好 安全、零开销抽象、并发 & 系统级 高性能、通用系统编程
编译模式 静态编译 静态编译 静态编译
内存管理 GC（垃圾回收） 所有权 + 借用系统（无 GC） 手动管理（可选智能指针）
并发模型 Goroutines + Channel（轻量线程） async/await + Send/Sync trait std::thread + 原生线程库
安全性 编译时类型安全，但有 GC 编译时内存 & 并发安全 编译时类型安全，但容易悬挂指针和 UB
性能 高，但有 GC 开销 接近 C++，零开销抽象 极高，可手动优化到极致
泛型 1.18+ 支持泛型 强大泛型 + trait 模板（template）
易用性 简单易学、上手快 学习曲线陡峭，但安全性高 学习曲线陡峭，容易踩坑
生态 云服务、微服务、网络库 系统编程、嵌入式、WebAssembly、区块链 系统、游戏、图形、高性能库

2️⃣ 内存管理对比

方面 Go Rust C++
管理方式 GC（自动回收） 所有权 & 借用 + 生命周期 手动 delete / new 或智能指针
悬挂指针 基本不会 编译器保证不会 很容易出现
内存泄漏 GC 避免大部分 编译器保证 RAII（几乎不会） 可能出现，需手动管理
性能影响 GC 停顿可能影响延迟 无 GC，性能可控 高性能，但需小心内存管理

3️⃣ 并发对比

语言 并发模型 优缺点
Go Goroutines + Channels 轻量级、易用、调度由 runtime 管理；可能 GC 暂停影响延迟
Rust async/await + Send/Sync 安全、零成本抽象，但需要掌握生命周期和 trait，学习曲线高
C++ std::thread / Boost / 原生线程 高度可控，性能最好，但容易出现死锁、数据竞争，需要手动管理同步

4️⃣ 安全性

安全性方面 Go Rust C++
类型安全 是 是 是
内存安全 依赖 GC 编译期保证 依赖开发者
并发安全 简单但不严格 编译期借用检查保证 开发者自己保证
越界访问 runtime panic 编译器 & borrow checker 阻止 可能出现 UB

5️⃣ 性能比较
C++：原生指针 + 零开销抽象 → 最快
Rust：接近 C++，无 GC，优化非常强
Go：有 GC，但 Goroutine 调度极快，适合网络/IO密集型

6️⃣ 泛型与抽象

语言 泛型 / 模板 特点
Go 1.18+ 泛型 类型安全，但语法简单
Rust trait + 泛型 零开销抽象，函数和类型都可以泛型化
C++ template 功能强大，但错误信息复杂，模板元编程复杂

7️⃣ 应用场景

语言 常见应用
Go 云服务、微服务、网络服务、CLI 工具
Rust 系统编程、嵌入式、WebAssembly、区块链、性能关键库
C++ 系统底层、游戏开发、图形渲染、高性能计算

🔹 总结建议

  1. 想快速上手、开发网络/服务端应用 → Go
  2. 想追求内存安全、零成本抽象、系统级开发 → Rust
  3. 极致性能、硬件控制、游戏或图形开发 → C++
