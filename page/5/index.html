    锁奥义

    查看当前出现的锁

    1.互斥锁与自旋锁

    • 互斥锁加锁失败后，线程会释放 CPU ，给其他线程；

      互斥锁是一种「独占锁」，比如当线程 A 加锁成功后，此时互斥锁已经被线程 A 独占了，只要线程 A 没有释放手中的锁，线程 B 加锁就会失败，于是就会释放 CPU 让给其他线程，既然线程 B 释放掉了 CPU，自然线程 B 加锁的代码就会被阻塞。

    • 自旋锁加锁失败后，线程会忙等待，直到它拿到锁；

      自旋锁是通过 CPU 提供的 CAS 函数（Compare And Swap），在「用户态」完成加锁和解锁操作，不会主动产生线程上下文切换，所以相比互斥锁来说，会快一些，开销也小一些。

      一般加锁的过程，包含两个步骤：

      第一步，查看锁的状态，如果锁是空闲的，则执行第二步；
      第二步，将锁设置为当前线程持有；

      CAS 函数就把这两个步骤合并成一条硬件级指令，形成原子指令，这样就保证了这两个步骤是不可分割的，要么一次性执行完两个步骤，要么两个步骤都不执行

      使用自旋锁的时候，当发生多线程竞争锁的情况，加锁失败的线程会「忙等待」，直到它拿到锁。这里的「忙等待」可以用 while 循环等待实现，不过最好是使用 CPU 提供的 PAUSE 指令来实现「忙等待」，因为可以减少循环等待时的耗电量

      自旋锁是最比较简单的一种锁，一直自旋，利用 CPU 周期，直到锁可用。需要注意，在单核 CPU 上，需要抢占式的调度器（即不断通过时钟中断一个线程，运行其他线程）。否则，自旋锁在单 CPU 上无法使用，因为一个自旋的线程永远不会放弃 CPU。

    特性 互斥锁 自旋锁
    性能开销成本 当两个线程是属于同一个进程，因为虚拟内存是共享的，所以在切换时，虚拟内存这些资源就保持不动，只需要切换线程的私有数据、寄存器等不共享的数据 需要注意，在单核 CPU 上，需要抢占式的调度器（即不断通过时钟中断一个线程，运行其他线程）。否则，自旋锁在单 CPU 上无法使用，因为一个自旋的线程永远不会放弃 CPU
    2.读写锁：读和写还有优先级区分

    由「读锁」和「写锁」两部分构成，如果只读取共享资源用「读锁」加锁，如果要修改共享资源则用「写锁」加锁

    工作原理：
    当写锁没有被线程持有时，多个线程可以并发地持有读锁，但是当写锁被线程持有后，其他线程获取读锁和写锁的操作都会阻塞

    读优先锁

    写优先锁

    但是这两种都会造成线程“饥饿”的问题，比如

    • 读优先锁：一直有读线程获取读锁，那么写线程将永远获取不到，造成写线程“饥饿”。
    • 写优先锁：如果⼀直有写线程获取写锁，读线程也会被「饿死」。

    所以我们可以搞一个公平读写锁
    公平读写锁⽐较简单的⼀种⽅式是：⽤队列把获取锁的线程排队，不管是写线程还是读线程都按照先进先出的原则加锁即可，这样读线程仍然可以并发，也不会出现「饥饿」的现象。

    3.乐观锁与悲观锁

    前面提到的互斥锁、自旋锁、读写锁，都是属于悲观锁。

    • 悲观锁：认为多线程同时修改共享资源的概率⽐较⾼，于是很容易出现冲突，所以访问共享资源前，先要上锁。

    • 前⾯提到的互斥锁、⾃旋锁、读写锁，都是属于悲观锁。

    • 乐观锁：假定冲突的概率很低，它的⼯作⽅式是：先修改完共享资源，再验证这段时间内有没有发⽣冲突，如果没有其他线程在修改资源，那么操作完成，如果发现有其他线程已经修改过这个资源，就放弃本次操作。另外虽然叫锁，但是乐观锁全程并没有加锁，所以它也叫⽆锁编程。

    一般会使用版本号机制或CAS算法实现

    电烙铁使用

    一、所需材料

    • 电烙铁（温度可调，280℃~350℃）
    • 焊锡丝（含助焊剂芯最佳）
    • 助焊剂（焊锡丝无助焊芯时使用）

    二、操作步骤

    1. 预热电烙铁

      • 将电烙铁调至目标温度（280℃~350℃）
      • 确保温度足够，否则焊锡无法顺利熔化

    2. 准备焊点

      • 清理焊接表面，有氧化层时用砂纸、钢丝刷或助焊剂清理
      • 表面干净、平整

    3. 涂助焊剂

      • 在焊接部位涂薄层助焊剂（若焊锡丝含助焊芯，可省略）

    4. 加热焊接点

      • 烙铁烙头接触焊点，同时靠近焊锡丝，让焊锡熔化流入焊点
      • 注意：不要先加热焊锡丝再碰焊点，应让焊点和焊锡同时受热

    5. 焊锡流动与覆盖

      • 焊锡应完全覆盖焊点，形成均匀焊珠
      • 焊接时间过长会烧坏元件，过短焊锡不牢固

    6. 冷却与检查

      • 移开电烙铁，自然冷却
      • 检查焊点是否光亮、均匀，无虚焊或桥连

    三、关键因素注意

    1. 电烙铁温度

      • 温度过低 → 焊锡不融化、附着不牢
      • 温度过高 → 烧坏元件、氧化焊点

    2. 电烙铁功率

      • 功率太低 → 加热慢、受热面积不足
      • 功率太高 → 不易控制温度
      • 一般30~60W适合大部分电子焊接

    3. 受热面积

      • 烙铁烙头与焊点充分接触
      • 大焊点用大烙铁头，小元件用尖头烙铁

    4. 表面状态

      • 有氧化层 → 焊锡难附着 → 需清理或涂助焊剂

    1. 白天光伏+储能 → 主要供夜晚和小家电使用

    导光器制作

    反光杯 + 聚光透镜 + 光纤 = 高效导光器

    反光杯：手电筒的灯胆
    聚光透镜就是：一半的凸透镜
    光纤：导光的

    优势：光强高、光斑小、光纤耦合效率高
    限制：光源功率、焦点热量、光纤耐热、精密对准
    可以说这是 DIY 高效率光纤引光器的最佳组合之一，比单透镜或单反光杯效率高很多。

    所需硬件

    核心部件

    • 光伏组件（Solar PV Modules / Solar Panels）
      作用：把太阳光转为直流电（DC）。
      要点：选单晶硅、高转换效率（≥19% 更优）、带 PID 抗衰能力。组件功率按屋顶面积/需求选择（如 300–540 W/panel）。
      数量 = 目标系统容量（kW） ÷ 单板功率（kW）。

    • 混合逆变器（Hybrid Inverter / PV Inverter with ESS）
      作用：DC→AC、MPPT、管理电池充放电、并网与离网切换。
      要点：支持双向充放电、并网认证、离网/备电输出、通信（RS485 / CAN / Wi-Fi）、峰值输出能力要匹配家中最大同时功率。
      常见规格：3kW / 5kW / 10kW 等；直流输入电压/最大 MPPT 电流要能接入你的 PV 阵列。

    • 储能电池（Battery Bank） — 推荐 LiFePO4（磷酸铁锂）
      作用：存储白天多余电能，用于夜间或停电时供电。
      要点：选择带 BMS 的电池包；标注循环寿命（≥3000 次@80% DOD 更好）；额定电压（48V 系统常见）或模块化 400V 系统（取决逆变器）。
      容量建议（家庭参考）：5 kWh / 10 kWh / 20 kWh。

    • 电池管理系统（BMS）
      作用：电池保护（过充、过放、均衡、温度保护）和与逆变器通讯。
      要点：必须与电池和逆变器兼容，支持报警与远程通信。

    AI Agent

    层次,核心组件,功能描述,对应你的 Agent OS 模块建议

    1. 接入层 (API),REST / WebSocket,接收自然语言指令（如：“去 GitHub 帮我点个 Star”）。,internal/adapter/http.go

    3. 执行层 (Executor),Playwright / Chromium,物理操作：真实的浏览器内核，处理页面渲染、JS 执行、Cookie 持久化。,internal/tools/browser/

    观察 (Observe) -> 思考 (Think) -> 决策 (Decide) -> 执行 (Act) 的闭环。

    • Observe (观察)：提取当前页面的可交互元素列表（Button, Input, Link）。
    • Think (思考)：LLM 根据当前任务目标分析这些元素。
    • Decide (决策)：LLM 输出标准格式的操作指令（例如：{“action”: “click”, “selector”: “#submit-btn”}）。
    • Act (执行)：调用 Playwright 执行动作并等待页面刷新，进入下一轮循环。

    一、语音验证（说话人识别）

    方案 方法 优点 适用场景
    Vosk + X-vector 离线语音验证 轻量级，树莓派可运行 本地语音助手

    二、语音唤醒（Wake Word Detection）

    • 需要一个始终在监听的“唤醒词”（如 Siri 监听“Hey Siri”）。
    • 解决方案：
      • Porcupine（轻量级，支持离线）
      • Snowboy（不再维护，但仍可用）
      • Mycroft Precise（开源，可训练自定义唤醒词）
      • Vosk + KeywordSpotter → 自定义关键词检测

    三、自然语言理解（Natural Language Understanding, NLU）

    • 解析用户的意图，比如“今天天气怎么样？” → 解析出“查询天气”。
    • 方案：
      • Rasa NLU（开源，可离线运行）
      • Snips NLU（轻量级，但 Snips 已被 Sonos 收购）
      • OpenAI GPT-4（需要联网，但效果强大）

    四、工作流程

    硬件需求

    • 树莓派 4B / 5
      • 推荐至少 4GB RAM，运行 ASR + 说话人识别时比较流畅。
    • 麦克风
      • USB 麦克风（简单易用，例如 TONOR TC-777）
      • 或 麦克风阵列（推荐 ReSpeaker 2/4/6-Mic Array for Raspberry Pi，带有降噪/回声消除）
      • 如果对说话人识别准确率要求高，阵列效果更好。
    • 存储
      • 至少 32GB microSD
      • 或者外接 SSD，ASR 模型会比较大。
    • （可选）扬声器/耳机：做语音交互时需要输出。

    软件与模块对应

    对应你流程里的各个步骤：

    1. 麦克风输入
      • 用 pyaudio / sounddevice 采集音频流。
      • 设置为 16kHz 单声道 PCM。
    2. Ring Buffer 缓存
      • 可以用 collections.deque 或者 sounddevice.RawInputStream 自带的回调缓存。
      • 缓存 1~3 秒的音频，保证唤醒词检测和语音片段提取。
    3. 唤醒词检测
      • 轻量：Porcupine（低资源占用，树莓派友好）
      • 可训练：Mycroft Precise
      • 自定义词：Vosk + KeywordSpotter
    4. 提取音频片段（1~2秒）
      • 当检测到唤醒词，立刻把 Ring Buffer 里的最后 1~2 秒 dump 出来保存为 .wav。
    5. 说话人识别（X-vector）
      • 依赖 pyannote.audio 或 SpeechBrain，输入音频片段，输出 speaker embedding → 与本地数据库比对。
      • 树莓派 4/5 能跑，但建议用轻量模型或外接 USB TPU（Coral USB Accelerator）。
    6. 身份确认
      • 如果 embedding 相似度 > 阈值（如 0.75），则确认说话人。
      • 否则忽略唤醒，避免被陌生人触发。
    7. 完整语音识别（ASR）
      • 用 Vosk（支持离线运行，中文/英文等都有预训练模型）。
      • Vosk-pi 版本可在树莓派直接跑，速度较慢，但可以用小模型（如 vosk-model-small-cn-0.3）。
