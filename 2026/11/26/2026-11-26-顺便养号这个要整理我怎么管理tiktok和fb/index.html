# 柬埔寨本地市场社媒矩阵从零搭建：FB + TikTok 账号策略与 Developer 配置顺序 ## 背景与场景 在柬埔寨（KH）落地 3D 打印品牌（Apex 3D Lab）的运营初期，需要同时建立 Facebook 和 TikTok 两个平台的账号资产，并完成 TikTok Developer 的 Sandbox 配置以打通 OAuth 授权流程。核心难点是：账号从零开始（无历史数据）、TikTok 在 KH 有养号要求、Developer 配置依赖真实账号才能进入 Sandbox target user。 --- ## 核心结论 1. **FB 在柬埔寨市场占有率 >80%，Marketplace + Messenger 是主要买卖通道**，优先级高于 TikTok；Page + Marketplace 组合是柬埔寨电商标配，第一周就能上。 2. **TikTok 建号必须用柬埔寨本地 SIM 卡注册**，不能用中/美 SIM；一台手机多号会被重罚，1人真实经营上限 2–3 个号。 3. **TikTok Sandbox target user 需要真实 TikTok 账号**，Developer 配置（Login Kit redirect URI / scopes）可以先行，但 OAuth 走通必须等账号建完并加入 Sandbox。 4. **养号冷启期前 7 天不发内容**，只刷 FYP + 点赞同类视频，让算法打好标签后再开始发布。 5. **scp 签名文件 + verify URL property 不依赖账号**，可以和建号并行操作，不要串行等待。 --- ## 实现方案 ### FB 侧：起步资产矩阵 **录入 nurture 系统（一条 curl）**： --- ### TikTok 侧：从零建号 + 养号时间线 **账号矩阵规划**： > 不要一次建 3 个号，账号关联强度高会连坐。 **主号从零建号操作时间线**： --- ### TikTok Developer 配置顺序（与建号并行） --- ## 避坑指南 **1. TikTok SIM 卡来源决定账号地区权重** 用中国/美国 SIM 注册的账号，FYP 推荐流量会走该国流量池，不会优先推给柬埔寨本地用户。即使后期切换语言和内容，账号地区标签已定，改不回来。建号必须在柬埔寨本地插当地 SIM。 **2. 养号期发内容会重置标签学习** Day 2–7 如果发了视频，系统会用视频内容覆盖掉你刷 FYP 喂的行为标签，冷启效果归零。养号期严格执行"只看不发"，到 Day 8 再发第一条。 **3. TikTok Sandbox OAuth 不能在没有 target user 的情况下测试** Sandbox 模式下，只有加入 target user 列表的账号才能完成 OAuth 授权。如果先跑 OAuth 流程，会在授权页卡住返回 `permission_denied`，报错不明显，容易误判为 redirect_uri 配置问题。正确顺序：**先建号 → 先加 target user → 再跑 OAuth**。 --- ## 底层机制 **TikTok 账号权重系统**的冷启逻辑：新账号没有历史行为数据，算法无法判断该把视频推给谁。养号期通过持续完播特定类目内容，给系统建立"这个用户喜欢 X 类内容"的信号，等第一条视频发出时，系统会优先把视频推给和该账号兴趣图谱相似的用户，冷启成功率显著高于直接发布。这也是为什么 Day 1 不能 follow 任何人——follow 行为会稀释兴趣标签的纯度。 **FB Marketplace 在柬埔寨的特殊地位**：柬埔寨正规电商平台（Shopee/Lazada）渗透率偏低，大量交易发生在 FB Marketplace + Messenger 链路上。Marketplace 商品可以直接关联到 Page 的 Inbox，买家询价走 Messenger，形成完整的"曝光→询价→成交"闭环，不需要独立建站或接第三方支付（Cash on Delivery 是 KH 主流）。
