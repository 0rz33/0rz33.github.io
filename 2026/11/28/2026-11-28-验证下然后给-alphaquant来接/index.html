# shanggu-quant API 对接指南：端点验证 + AlphaQuant 接入全流程 ## 背景与场景 shanggu 实盘分析模块（`shanggu-quant`）部署在 mini 节点（`:8010`），对外暴露分析接口和 KB 直查接口，供 AlphaQuant 量化平台消费。在正式交接前需验证路由是否挂载、鉴权是否生效，避免 AlphaQuant 侧集成时踩到"接了但没数据"或"路由 404"的坑。本文记录验证过程和完整对接合约。 --- ## 核心结论 1. **用"不带 token 探一遍"验证路由**：合法挂载的端点返回 `401/403`，未挂载返回 `404`。全 auth 挡说明路由正确、中间件生效，带 token 即通。 2. **`REQUIRE_CHAT_AUTH` 开启时 API Key 不能填 `not-needed`**：mini 节点开了聊天鉴权，`Authorization: Bearer not-needed` 会被拒，必须填真实 `ADMIN_TOKEN`。 3. **KB grounding 依赖爬虫有料**：`hanlin_quant`（审核）/ `hanlin_quant_unaudited`（未审核）两张表为空时，`shanggu-quant` 仍能用 Opus 常识回答，但 `sources_cited` 字段为空列表——这是正常降级，不是 bug。 4. **KB 直查走 `/admin/kb/*` 路径，非 `/v1/`**：三条端点（list/doc/search）的鉴权头和 chat 一样用 `Bearer `，但 base path 不同，不能混用。 5. **分析出参顶层有 `sources_cited`**：每条引用带 `trust: verified|unverified`，消费方（AlphaQuant）应按此字段区分信源可信度，不要把 unverified 来源的结论当作实盘依据。 --- ## 实现方案 ### 0. 前置验证（不带 token 探路） | 结果 | 含义 | |---|---| | `401 / 403` | ✅ 路由在线，鉴权正常 | | `404` | ❌ 路由未注册，检查 handler 挂载 | | `200`（无 token） | ❌ 鉴权中间件漏挂 | --- ### 1. KB 无料 ≠ 接口故障** 新环境或爬虫停跑时，`quant-list` 返回 `{"docs":[],"count":0}`，`sources_cited` 为 `[]`——这是正常降级，模型会用 Opus 通识回答。接入方不要把"空 sources_cited"当做报警条件，应该监控爬虫是否持续入库。 **3. `stream=true` 时 `sources_cited` 位置不同** 流式响应中 `sources_cited` 在最后一个 SSE chunk 的 `delta` 里，非流式时在顶层。AlphaQuant 若用流式消费，需要在 `[DONE]` 前的最后一帧里提取，不要在首帧找。 --- ## 底层机制 **两张信任等级表的设计意图** `hanlin_quant`（审核表）存经人工或规则校验的可信源，查询时默认优先；`hanlin_quant_unaudited`（未审核表）存爬虫原始落库、TTL 30 天自动过期，适合时效性强但未核实的信源（如 X/外媒）。`trust` 字段在 grounding 时透传给消费方，让 AlphaQuant 侧自己决定是否展示未审核引用——分析引擎不替消费方做信源判断，只做透传标记。 **鉴权分层** `:8010` 节点有两条鉴权中间件：`authAdmin`（校验 `ADMIN_TOKEN`，管 `/admin/*` 和 `/mcp/*`）和 `chatAuth`（校验 `REQUIRE_CHAT_AUTH`，管 `/v1/chat/*`）。`ADMIN_TOKEN` 同时满足两者，所以 AlphaQuant 只需配一个 key 就能打通全部端点。
