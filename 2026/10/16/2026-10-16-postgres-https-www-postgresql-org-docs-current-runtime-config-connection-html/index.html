SSL](runtime-config-connection.html#RUNTIME-CONFIG-CONNECTION-SSL)]{.sect2} ::: ::::::: {#RUNTIME-CONFIG-CONNECTION-SETTINGS .sect2} ::::: titlepage :::: {} ::: {} ### 19.3.1. Connection Settings [\#](#RUNTIME-CONFIG-CONNECTION-SETTINGS){.id_link} {#connection-settings .title} ::: :::: ::::: ::: variablelist [`listen_addresses`{.varname} (`string`{.type}) []{#id-1.6.6.6.2.2.1.1.3 .indexterm}]{.term} [\#](#GUC-LISTEN-ADDRESSES){.id_link} : Specifies the TCP/IP address(es) on which the server is to listen for connections from client applications. The value takes the form of a comma-separated list of host names and/or numeric IP addresses. The special entry `*`{.literal} corresponds to all available IP interfaces. The entry `0.0.0.0`{.literal} allows listening for all IPv4 addresses and `::`{.literal} allows listening for all IPv6 addresses. If the list is empty, the server does not listen on any IP interface at all, in which case only Unix-domain sockets can be used to connect to it. If the list is not empty, the server will start if it can listen on at least one TCP/IP address. A warning will be emitted for any TCP/IP address which cannot be opened. The default value is [localhost]{.systemitem}, which allows only local TCP/IP ["[loopback]{.quote}"]{.quote} connections to be made. While client authentication ([Chapter 20](client-authentication.html "Chapter 20. Client Authentication"){.xref}) allows fine-grained control over who can access the server, `listen_addresses`{.varname} controls which interfaces accept connection attempts, which can help prevent repeated malicious connection requests on insecure network interfaces. This parameter can only be set at server start. [`port`{.varname} (`integer`{.type}) []{#id-1.6.6.6.2.2.2.1.3 .indexterm}]{.term} [\#](#GUC-PORT){.id_link} : The TCP port the server listens on; 5432 by default. Note that the same port number is used for all IP addresses the server listens on. This parameter can only be set at server start. [`max_connections`{.varname} (`integer`{.type}) []{#id-1.6.6.6.2.2.3.1.3 .indexterm}]{.term} [\#](#GUC-MAX-CONNECTIONS){.id_link} : Determines the maximum number of concurrent connections to the database server. The default is typically 100 connections, but might be less if your kernel settings will not support it (as determined during [initdb]{.application}). This parameter can only be set at server start. [PostgreSQL]{.productname} sizes certain resources based directly on the value of `max_connections`{.varname}. Increasing its value leads to higher allocation of those resources, including shared memory. When running a standby server, you must set this parameter to the same or higher value than on the primary server. Otherwise, queries will not be allowed in the standby server. [`reserved_connections`{.varname} (`integer`{.type}) []{#id-1.6.6.6.2.2.4.1.3 .indexterm}]{.term} [\#](#GUC-RESERVED-CONNECTIONS){.id_link} : Determines the number of connection ["[slots]{.quote}"]{.quote} that are reserved for connections by roles with privileges of the [pg_use_reserved_connections](predefined-roles.html#PREDEFINED-ROLE-PG-USE-RESERVED-CONNECTIONS){.xref} role. Whenever the number of free connection slots is greater than [superuser_reserved_connections](runtime-config-connection.html#GUC-SUPERUSER-RESERVED-CONNECTIONS){.xref} but less than or equal to the sum of `superuser_reserved_connections`{.varname} and `reserved_connections`{.varname}, new connections will be accepted only for superusers and roles with privileges of `pg_use_reserved_connections`{.literal}. If `superuser_reserved_connections`{.varname} or fewer connection slots are available, new connections will be accepted only for superusers. The default value is zero connections. The value must be less than `max_connections`{.varname} minus `superuser_reserved_connections`{.varname}. This parameter can only be set at server start. [`superuser_reserved_connections`{.varname} (`integer`{.type}) []{#id-1.6.6.6.2.2.5.1.3 .indexterm}]{.term} [\#](#GUC-SUPERUSER-RESERVED-CONNECTIONS){.id_link} : Determines the number of connection ["[slots]{.quote}"]{.quote} that are reserved for connections by [PostgreSQL]{.productname} superusers. At most [max_connections](runtime-config-connection.html#GUC-MAX-CONNECTIONS){.xref} connections can ever be active simultaneously. Whenever the number of active concurrent connections is at least `max_connections`{.varname} minus `superuser_reserved_connections`{.varname}, new connections will be accepted only for superusers. The connection slots reserved by this parameter are intended as final reserve for emergency use after the slots reserved by [reserved_connections](runtime-config-connection.html#GUC-RESERVED-CONNECTIONS){.xref} have been exhausted. The default value is three connections. The value must be less than `max_connections`{.varname} minus `reserved_connections`{.varname}. This parameter can only be set at server start. [`unix_socket_directories`{.varname} (`string`{.type}) []{#id-1.6.6.6.2.2.6.1.3 .indexterm}]{.term} [\#](#GUC-UNIX-SOCKET-DIRECTORIES){.id_link} : Specifies the directory of the Unix-domain socket(s) on which the server is to listen for connections from client applications. Multiple sockets can be created by listing multiple directories separated by commas. Whitespace between entries is ignored; surround a directory name with double quotes if you need to include whitespace or commas in the name. An empty value specifies not listening on any Unix-domain sockets, in which case only TCP/IP sockets can be used to connect to the server. A value that starts with `@`{.literal} specifies that a Unix-domain socket in the abstract namespace should be created (currently supported on Linux only). In that case, this value does not specify a ["[directory]{.quote}"]{.quote} but a prefix from which the actual socket name is computed in the same manner as for the file-system namespace. While the abstract socket name prefix can be chosen freely, since it is not a file-system location, the convention is to nonetheless use file-system-like values such as `@/tmp`{.literal}. The default value is normally `/tmp`{.filename}, but that can be changed at build time. On Windows, the default is empty, which means no Unix-domain socket is created by default. This parameter can only be set at server start. In addition to the socket file itself, which is named `.s.PGSQL.`{.literal}*`nnnn`* where *`nnnn`* is the server\'s port number, an ordinary file named `.s.PGSQL.`{.literal}*`nnnn`*`.lock`{.literal} will be created in each of the `unix_socket_directories`{.varname} directories. Neither file should ever be removed manually. For sockets in the abstract namespace, no lock file is created. [`unix_socket_group`{.varname} (`string`{.type}) []{#id-1.6.6.6.2.2.7.1.3 .indexterm}]{.term} [\#](#GUC-UNIX-SOCKET-GROUP){.id_link} : Sets the owning group of the Unix-domain socket(s). (The owning user of the sockets is always the user that starts the server.) In combination with the parameter `unix_socket_permissions`{.varname} this can be used as an additional access control mechanism for Unix-domain connections. By default this is the empty string, which uses the default group of the server user. This parameter can only be set at server start. This parameter is not supported on Windows. Any setting will be ignored. Also, sockets in the abstract namespace have no file owner, so this setting is also ignored in that case. [`unix_socket_permissions`{.varname} (`integer`{.type}) []{#id-1.6.6.6.2.2.8.1.3 .indexterm}]{.term} [\#](#GUC-UNIX-SOCKET-PERMISSIONS){.id_link} : Sets the access permissions of the Unix-domain socket(s). Unix-domain sockets use the usual Unix file system permission set. The parameter value is expected to be a numeric mode specified in the format accepted by the `chmod`{.function} and `umask`{.function} system calls. (To use the customary octal format the number must start with a `0`{.literal} (zero).) The default permissions are `0777`{.literal}, meaning anyone can connect. Reasonable alternatives are `0770`{.literal} (only user and group, see also `unix_socket_group`{.varname}) and `0700`{.literal} (only user). (Note that for a Unix-domain socket, only write permission matters, so there is no point in setting or revoking read or execute permissions.) This access control mechanism is independent of the one described in [Chapter 20](client-authentication.html "Chapter 20. Client Authentication"){.xref}. This parameter can only be set at server start. This parameter is irrelevant on systems, notably Solaris as of Solaris 10, that ignore socket permissions entirely. There, one can achieve a similar effect by pointing `unix_socket_directories`{.varname} to a directory having search permission limited to the desired audience. Sockets in the abstract namespace have no file permissions, so this setting is also ignored in that case. [`bonjour`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.2.2.9.1.3 .indexterm}]{.term} [\#](#GUC-BONJOUR){.id_link} : Enables advertising the server\'s existence via [Bonjour]{.productname}. The default is off. This parameter can only be set at server start. [`bonjour_name`{.varname} (`string`{.type}) []{#id-1.6.6.6.2.2.10.1.3 .indexterm}]{.term} [\#](#GUC-BONJOUR-NAME){.id_link} : Specifies the [Bonjour]{.productname} service name. The computer name is used if this parameter is set to the empty string `''`{.literal} (which is the default). This parameter is ignored if the server was not compiled with [Bonjour]{.productname} support. This parameter can only be set at server start. ::: ::::::: ::::::: {#RUNTIME-CONFIG-TCP-SETTINGS .sect2} ::::: titlepage :::: {} ::: {} ### 19.3.2. TCP Settings [\#](#RUNTIME-CONFIG-TCP-SETTINGS){.id_link} {#tcp-settings .title} ::: :::: ::::: ::: variablelist [`tcp_keepalives_idle`{.varname} (`integer`{.type}) []{#id-1.6.6.6.3.2.1.1.3 .indexterm}]{.term} [\#](#GUC-TCP-KEEPALIVES-IDLE){.id_link} : Specifies the amount of time with no network activity after which the operating system should send a TCP keepalive message to the client. If this value is specified without units, it is taken as seconds. A value of 0 (the default) selects the operating system\'s default. On Windows, setting a value of 0 will set this parameter to 2 hours, since Windows does not provide a way to read the system default value. This parameter is supported only on systems that support `TCP_KEEPIDLE`{.symbol} or an equivalent socket option, and on Windows; on other systems, it must be zero. In sessions connected via a Unix-domain socket, this parameter is ignored and always reads as zero. [`tcp_keepalives_interval`{.varname} (`integer`{.type}) []{#id-1.6.6.6.3.2.2.1.3 .indexterm}]{.term} [\#](#GUC-TCP-KEEPALIVES-INTERVAL){.id_link} : Specifies the amount of time after which a TCP keepalive message that has not been acknowledged by the client should be retransmitted. If this value is specified without units, it is taken as seconds. A value of 0 (the default) selects the operating system\'s default. On Windows, setting a value of 0 will set this parameter to 1 second, since Windows does not provide a way to read the system default value. This parameter is supported only on systems that support `TCP_KEEPINTVL`{.symbol} or an equivalent socket option, and on Windows; on other systems, it must be zero. In sessions connected via a Unix-domain socket, this parameter is ignored and always reads as zero. [`tcp_keepalives_count`{.varname} (`integer`{.type}) []{#id-1.6.6.6.3.2.3.1.3 .indexterm}]{.term} [\#](#GUC-TCP-KEEPALIVES-COUNT){.id_link} : Specifies the number of TCP keepalive messages that can be lost before the server\'s connection to the client is considered dead. A value of 0 (the default) selects the operating system\'s default. This parameter is supported only on systems that support `TCP_KEEPCNT`{.symbol} or an equivalent socket option (which does not include Windows); on other systems, it must be zero. In sessions connected via a Unix-domain socket, this parameter is ignored and always reads as zero. [`tcp_user_timeout`{.varname} (`integer`{.type}) []{#id-1.6.6.6.3.2.4.1.3 .indexterm}]{.term} [\#](#GUC-TCP-USER-TIMEOUT){.id_link} : Specifies the amount of time that transmitted data may remain unacknowledged before the TCP connection is forcibly closed. If this value is specified without units, it is taken as milliseconds. A value of 0 (the default) selects the operating system\'s default. This parameter is supported only on systems that support `TCP_USER_TIMEOUT`{.symbol} (which does not include Windows); on other systems, it must be zero. In sessions connected via a Unix-domain socket, this parameter is ignored and always reads as zero. [`client_connection_check_interval`{.varname} (`integer`{.type}) []{#id-1.6.6.6.3.2.5.1.3 .indexterm}]{.term} [\#](#GUC-CLIENT-CONNECTION-CHECK-INTERVAL){.id_link} : Sets the time interval between optional checks that the client is still connected, while running queries. The check is performed by polling the socket, and allows long running queries to be aborted sooner if the kernel reports that the connection is closed. This option relies on kernel events exposed by Linux, macOS, illumos and the BSD family of operating systems, and is not currently available on other systems. If the value is specified without units, it is taken as milliseconds. The default value is `0`{.literal}, which disables connection checks. Without connection checks, the server will detect the loss of the connection only at the next interaction with the socket, when it waits for, receives or sends data. For the kernel itself to detect lost TCP connections reliably and within a known timeframe in all scenarios including network failure, it may also be necessary to adjust the TCP keepalive settings of the operating system, or the [tcp_keepalives_idle](runtime-config-connection.html#GUC-TCP-KEEPALIVES-IDLE){.xref}, [tcp_keepalives_interval](runtime-config-connection.html#GUC-TCP-KEEPALIVES-INTERVAL){.xref} and [tcp_keepalives_count](runtime-config-connection.html#GUC-TCP-KEEPALIVES-COUNT){.xref} settings of [PostgreSQL]{.productname}. ::: ::::::: ::::::: {#RUNTIME-CONFIG-CONNECTION-AUTHENTICATION .sect2} ::::: titlepage :::: {} ::: {} ### 19.3.3. Authentication [\#](#RUNTIME-CONFIG-CONNECTION-AUTHENTICATION){.id_link} {#authentication .title} ::: :::: ::::: ::: variablelist [`authentication_timeout`{.varname} (`integer`{.type}) []{#id-1.6.6.6.4.2.1.1.3 .indexterm} []{#id-1.6.6.6.4.2.1.1.4 .indexterm} []{#id-1.6.6.6.4.2.1.1.5 .indexterm}]{.term} [\#](#GUC-AUTHENTICATION-TIMEOUT){.id_link} : Maximum amount of time allowed to complete client authentication. If a would-be client has not completed the authentication protocol in this much time, the server closes the connection. This prevents hung clients from occupying a connection indefinitely. If this value is specified without units, it is taken as seconds. The default is one minute (`1m`{.literal}). This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`password_encryption`{.varname} (`enum`{.type}) []{#id-1.6.6.6.4.2.2.1.3 .indexterm}]{.term} [\#](#GUC-PASSWORD-ENCRYPTION){.id_link} : When a password is specified in [[CREATE ROLE]{.refentrytitle}](sql-createrole.html "CREATE ROLE"){.xref} or [[ALTER ROLE]{.refentrytitle}](sql-alterrole.html "ALTER ROLE"){.xref}, this parameter determines the algorithm to use to encrypt the password. Possible values are `scram-sha-256`{.literal}, which will encrypt the password with SCRAM-SHA-256, and `md5`{.literal}, which stores the password as an MD5 hash. The default is `scram-sha-256`{.literal}. Note that older clients might lack support for the SCRAM authentication mechanism, and hence not work with passwords encrypted with SCRAM-SHA-256. See [Section 20.5](auth-password.html "20.5. Password Authentication"){.xref} for more details. ::: warning ### Warning {#warning .title} Support for MD5-encrypted passwords is deprecated and will be removed in a future release of [PostgreSQL]{.productname}. Refer to [Section 20.5](auth-password.html "20.5. Password Authentication"){.xref} for details about migrating to another password type. ::: [`scram_iterations`{.varname} (`integer`{.type}) []{#id-1.6.6.6.4.2.3.1.3 .indexterm}]{.term} [\#](#GUC-SCRAM-ITERATIONS){.id_link} : The number of computational iterations to be performed when encrypting a password using SCRAM-SHA-256. The default is `4096`{.literal}. A higher number of iterations provides additional protection against brute-force attacks on stored passwords, but makes authentication slower. Changing the value has no effect on existing passwords encrypted with SCRAM-SHA-256 as the iteration count is fixed at the time of encryption. In order to make use of a changed value, a new password must be set. ::: note ### Note {#note .title} If a role password was created with a different iteration count than the value of `scram_iterations`{.literal} specified in the `postgresql.conf`{.filename} file or on the server command line, an unauthenticated user can discern the existence of the role by observing discrepancies in the server\'s responses to connection attempts. If you find this concerning, ensure that all role passwords are created with `scram_iterations`{.literal} set to the value specified in the `postgresql.conf`{.filename} file or on the server command line. ::: [`md5_password_warnings`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.4.2.4.1.3 .indexterm}]{.term} [\#](#GUC-MD5-PASSWORD-WARNINGS){.id_link} : Controls whether a `WARNING`{.literal} about MD5 password deprecation is produced when a `CREATE ROLE`{.command} or `ALTER ROLE`{.command} statement sets an MD5-encrypted password. The default value is `on`{.literal}. [`krb_server_keyfile`{.varname} (`string`{.type}) []{#id-1.6.6.6.4.2.5.1.3 .indexterm}]{.term} [\#](#GUC-KRB-SERVER-KEYFILE){.id_link} : Sets the location of the server\'s Kerberos key file. The default is `FILE:/usr/local/pgsql/etc/krb5.keytab`{.filename} (where the directory part is whatever was specified as `sysconfdir`{.varname} at build time; use `pg_config --sysconfdir`{.literal} to determine that). If this parameter is set to an empty string, it is ignored and a system-dependent default is used. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. See [Section 20.6](gssapi-auth.html "20.6. GSSAPI Authentication"){.xref} for more information. [`krb_caseins_users`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.4.2.6.1.3 .indexterm}]{.term} [\#](#GUC-KRB-CASEINS-USERS){.id_link} : Sets whether GSSAPI user names should be treated case-insensitively. The default is `off`{.literal} (case sensitive). This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`gss_accept_delegation`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.4.2.7.1.3 .indexterm}]{.term} [\#](#GUC-GSS-ACCEPT-DELEGATION){.id_link} : Sets whether GSSAPI delegation should be accepted from the client. The default is `off`{.literal} meaning credentials from the client will [*not*]{.emphasis} be accepted. Changing this to `on`{.literal} will make the server accept credentials delegated to it from the client. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`oauth_validator_libraries`{.varname} (`string`{.type}) []{#id-1.6.6.6.4.2.8.1.3 .indexterm}]{.term} [\#](#GUC-OAUTH-VALIDATOR-LIBRARIES){.id_link} : The library/libraries to use for validating OAuth connection tokens. If only one validator library is provided, it will be used by default for any OAuth connections; otherwise, all [`oauth`{.literal} HBA entries](auth-oauth.html "20.15. OAuth Authorization/Authentication"){.link} must explicitly set a `validator`{.literal} chosen from this list. If set to an empty string (the default), OAuth connections will be refused. This parameter can only be set in the `postgresql.conf`{.filename} file. Validator modules must be implemented/obtained separately; [PostgreSQL]{.productname} does not ship with any default implementations. For more information on implementing OAuth validators, see [Chapter 50](oauth-validators.html "Chapter 50. OAuth Validator Modules"){.xref}. ::: ::::::: ::::::: {#RUNTIME-CONFIG-CONNECTION-SSL .sect2} ::::: titlepage :::: {} ::: {} ### 19.3.4. SSL [\#](#RUNTIME-CONFIG-CONNECTION-SSL){.id_link} {#ssl .title} ::: :::: ::::: See [Section 18.9](ssl-tcp.html "18.9. Secure TCP/IP Connections with SSL"){.xref} for more information about setting up SSL. The configuration parameters for controlling transfer encryption using TLS protocols are named `ssl`{.literal} for historic reasons, even though support for the SSL protocol has been deprecated. SSL is in this context used interchangeably with TLS. ::: variablelist [`ssl`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.5.3.1.1.3 .indexterm}]{.term} [\#](#GUC-SSL){.id_link} : Enables SSL connections. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is `off`{.literal}. [`ssl_ca_file`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.2.1.3 .indexterm}]{.term} [\#](#GUC-SSL-CA-FILE){.id_link} : Specifies the name of the file containing the SSL server certificate authority (CA). Relative paths are relative to the data directory. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is empty, meaning no CA file is loaded, and client certificate verification is not performed. [`ssl_cert_file`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.3.1.3 .indexterm}]{.term} [\#](#GUC-SSL-CERT-FILE){.id_link} : Specifies the name of the file containing the SSL server certificate. Relative paths are relative to the data directory. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is `server.crt`{.filename}. [`ssl_crl_file`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.4.1.3 .indexterm}]{.term} [\#](#GUC-SSL-CRL-FILE){.id_link} : Specifies the name of the file containing the SSL client certificate revocation list (CRL). Relative paths are relative to the data directory. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is empty, meaning no CRL file is loaded (unless [ssl_crl_dir](runtime-config-connection.html#GUC-SSL-CRL-DIR){.xref} is set). [`ssl_crl_dir`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.5.1.3 .indexterm}]{.term} [\#](#GUC-SSL-CRL-DIR){.id_link} : Specifies the name of the directory containing the SSL client certificate revocation list (CRL). Relative paths are relative to the data directory. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is empty, meaning no CRLs are used (unless [ssl_crl_file](runtime-config-connection.html#GUC-SSL-CRL-FILE){.xref} is set). The directory needs to be prepared with the [OpenSSL]{.productname} command `openssl rehash`{.literal} or `c_rehash`{.literal}. See its documentation for details. When using this setting, CRLs in the specified directory are loaded on-demand at connection time. New CRLs can be added to the directory and will be used immediately. This is unlike [ssl_crl_file](runtime-config-connection.html#GUC-SSL-CRL-FILE){.xref}, which causes the CRL in the file to be loaded at server start time or when the configuration is reloaded. Both settings can be used together. [`ssl_key_file`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.6.1.3 .indexterm}]{.term} [\#](#GUC-SSL-KEY-FILE){.id_link} : Specifies the name of the file containing the SSL server private key. Relative paths are relative to the data directory. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is `server.key`{.filename}. [`ssl_tls13_ciphers`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.7.1.3 .indexterm}]{.term} [\#](#GUC-SSL-TLS13-CIPHERS){.id_link} : Specifies a list of cipher suites that are allowed by connections using TLS version 1.3. Multiple cipher suites can be specified by using a colon separated list. If left blank, the default set of cipher suites in [OpenSSL]{.productname} will be used. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`ssl_ciphers`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.8.1.3 .indexterm}]{.term} [\#](#GUC-SSL-CIPHERS){.id_link} : Specifies a list of SSL ciphers that are allowed by connections using TLS version 1.2 and lower, see [ssl_tls13_ciphers](runtime-config-connection.html#GUC-SSL-TLS13-CIPHERS){.xref} for TLS version 1.3 connections. See the [[ciphers]{.refentrytitle}]{.citerefentry} manual page in the [OpenSSL]{.productname} package for the syntax of this setting and a list of supported values. The default value is `HIGH:MEDIUM:+3DES:!aNULL`{.literal}. The default is usually a reasonable choice unless you have specific security requirements. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. Explanation of the default value: ::: variablelist [`HIGH`{.literal}]{.term} [\#](#GUC-SSL-CIPHERS-HIGH){.id_link} : Cipher suites that use ciphers from `HIGH`{.literal} group (e.g., AES, Camellia, 3DES) [`MEDIUM`{.literal}]{.term} [\#](#GUC-SSL-CIPHERS-MEDIUM){.id_link} : Cipher suites that use ciphers from `MEDIUM`{.literal} group (e.g., RC4, SEED) [`+3DES`{.literal}]{.term} [\#](#GUC-SSL-CIPHERS-PLUS-3DES){.id_link} : The [OpenSSL]{.productname} default order for `HIGH`{.literal} is problematic because it orders 3DES higher than AES128. This is wrong because 3DES offers less security than AES128, and it is also much slower. `+3DES`{.literal} reorders it after all other `HIGH`{.literal} and `MEDIUM`{.literal} ciphers. [`!aNULL`{.literal}]{.term} [\#](#GUC-SSL-CIPHERS-NOT-ANULL){.id_link} : Disables anonymous cipher suites that do no authentication. Such cipher suites are vulnerable to MITM attacks and therefore should not be used. ::: Available cipher suite details will vary across [OpenSSL]{.productname} versions. Use the command `openssl ciphers -v 'HIGH:MEDIUM:+3DES:!aNULL'`{.literal} to see actual details for the currently installed [OpenSSL]{.productname} version. Note that this list is filtered at run time based on the server key type. [`ssl_prefer_server_ciphers`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.5.3.9.1.3 .indexterm}]{.term} [\#](#GUC-SSL-PREFER-SERVER-CIPHERS){.id_link} : Specifies whether to use the server\'s SSL cipher preferences, rather than the client\'s. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is `on`{.literal}. [PostgreSQL]{.productname} versions before 9.4 do not have this setting and always use the client\'s preferences. This setting is mainly for backward compatibility with those versions. Using the server\'s preferences is usually better because it is more likely that the server is appropriately configured. [`ssl_groups`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.10.1.3 .indexterm}]{.term} [\#](#GUC-SSL-GROUPS){.id_link} : Specifies the named group to use for TLS key exchange. It needs to be supported by all clients that connect. Multiple groups can be specified by using a colon-separated list. It does not need to match the key type used by the server certificate. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. The default is `X25519:prime256v1`{.literal}. [OpenSSL]{.productname} names for the most common groups are: `prime256v1`{.literal} (NIST P-256), `secp384r1`{.literal} (NIST P-384), `secp521r1`{.literal} (NIST P-521). An incomplete list of available groups can be shown with the command `openssl ecparam -list_curves`{.command}. Not all of them are usable with TLS though, and many supported group names and aliases are omitted. In [PostgreSQL]{.productname} versions before 18.0 this setting was named `ssl_ecdh_curve`{.literal} and only accepted a single value. [`ssl_min_protocol_version`{.varname} (`enum`{.type}) []{#id-1.6.6.6.5.3.11.1.3 .indexterm}]{.term} [\#](#GUC-SSL-MIN-PROTOCOL-VERSION){.id_link} : Sets the minimum SSL/TLS protocol version to use. Valid values are currently: `TLSv1`{.literal}, `TLSv1.1`{.literal}, `TLSv1.2`{.literal}, `TLSv1.3`{.literal}. Older versions of the [OpenSSL]{.productname} library do not support all values; an error will be raised if an unsupported setting is chosen. Protocol versions before TLS 1.0, namely SSL version 2 and 3, are always disabled. The default is `TLSv1.2`{.literal}, which satisfies industry best practices as of this writing. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`ssl_max_protocol_version`{.varname} (`enum`{.type}) []{#id-1.6.6.6.5.3.12.1.3 .indexterm}]{.term} [\#](#GUC-SSL-MAX-PROTOCOL-VERSION){.id_link} : Sets the maximum SSL/TLS protocol version to use. Valid values are as for [ssl_min_protocol_version](runtime-config-connection.html#GUC-SSL-MIN-PROTOCOL-VERSION){.xref}, with addition of an empty string, which allows any protocol version. The default is to allow any version. Setting the maximum protocol version is mainly useful for testing or if some component has issues working with a newer protocol. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`ssl_dh_params_file`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.13.1.3 .indexterm}]{.term} [\#](#GUC-SSL-DH-PARAMS-FILE){.id_link} : Specifies the name of the file containing Diffie-Hellman parameters used for so-called ephemeral DH family of SSL ciphers. The default is empty, in which case compiled-in default DH parameters used. Using custom DH parameters reduces the exposure if an attacker manages to crack the well-known compiled-in DH parameters. You can create your own DH parameters file with the command `openssl dhparam -out dhparams.pem 2048`{.command}. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`ssl_passphrase_command`{.varname} (`string`{.type}) []{#id-1.6.6.6.5.3.14.1.3 .indexterm}]{.term} [\#](#GUC-SSL-PASSPHRASE-COMMAND){.id_link} : Sets an external command to be invoked when a passphrase for decrypting an SSL file such as a private key needs to be obtained. By default, this parameter is empty, which means the built-in prompting mechanism is used. The command must print the passphrase to the standard output and exit with code 0. In the parameter value, `%p`{.literal} is replaced by a prompt string. (Write `%%`{.literal} for a literal `%`{.literal}.) Note that the prompt string will probably contain whitespace, so be sure to quote adequately. A single newline is stripped from the end of the output if present. The command does not actually have to prompt the user for a passphrase. It can read it from a file, obtain it from a keychain facility, or similar. It is up to the user to make sure the chosen mechanism is adequately secure. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. [`ssl_passphrase_command_supports_reload`{.varname} (`boolean`{.type}) []{#id-1.6.6.6.5.3.15.1.3 .indexterm}]{.term} [\#](#GUC-SSL-PASSPHRASE-COMMAND-SUPPORTS-RELOAD){.id_link} : This parameter determines whether the passphrase command set by `ssl_passphrase_command`{.varname} will also be called during a configuration reload if a key file needs a passphrase. If this parameter is `off`{.literal} (the default), then `ssl_passphrase_command`{.varname} will be ignored during a reload and the SSL configuration will not be reloaded if a passphrase is needed. That setting is appropriate for a command that requires a TTY for prompting, which might not be available when the server is running. Setting this parameter to on might be appropriate if the passphrase is obtained from a file, for example. This parameter must be set to `on`{.literal} when running on [Windows]{.systemitem} since all connections will perform a configuration reload due to the different process model of that platform. This parameter can only be set in the `postgresql.conf`{.filename} file or on the server command line. ::: ::::::: ::::::::::::::::::::::::::: ::: navfooter ------------------------------------------------------------------------ ----------------------------------------------------------------------------------- ----------------------------------------------------------------------------- ----------------------------------------------------------------------------------- [Prev](runtime-config-file-locations.html "19.2. File Locations"){accesskey="p"}  [Up](runtime-config.html "Chapter 19. Server Configuration"){accesskey="u"}  [Next](runtime-config-resource.html "19.4. Resource Consumption"){accesskey="n"} 19.2. File Locations  [Home](index.html "PostgreSQL 18.6 Documentation"){accesskey="h"}  19.4. Resource Consumption ----------------------------------------------------------------------------------- ----------------------------------------------------------------------------- ----------------------------------------------------------------------------------- ::: :::::::::::::::::::::::::::::: ::: {#docComments} ## Submit correction If you see anything in the documentation that is not correct, does not match your experience with the particular feature or requires further clarification, please use [this form](/account/comments/new/18/runtime-config-connection.html/){rel="nofollow"} to report a documentation issue. ::: ::::::::::::::::::::::::::::::::::::::::::::: :::::::::::::::::::::::::::::::::::::::::::::: ::::::::::::::::::::::::::::::::::::::::::::::: ::: container [Policies](/about/policies/) \| [Code of Conduct](/about/policies/coc/) \| [About PostgreSQL](/about/) \| [Contact](/about/contact/)\ Copyright © 1996-2026 The PostgreSQL Global Development Group :::
