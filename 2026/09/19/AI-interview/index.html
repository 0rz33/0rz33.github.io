一、 Agent 编排与多 Agent 协作

1. 题目：在构建企业级 Agent 时，如何保证工具调用（Tool Calling）的可靠性，特别是涉及 CRM、工单等内部系统写操作时？

  • 参考答案要点：
    • [cite_start]规范封装： 对内部系统封装为 Tool 时，需统一 Schema 规范，并集成鉴权、参数校验、幂等与重试机制 [cite: 10, 26]。
    • [cite_start]链路闭环： 结合“计划-执行-校验”链路，在高风险操作前引入模拟执行（dry-run）或人工审批节点，降低生产事故风险 [cite: 10, 27]。
    • [cite_start]安全审计： 必须具备 RBAC 权限模型、审计日志与敏感字段（PII）脱敏处理，确保 Agent 在授权范围内操作 [cite: 4, 8, 23]。

2. 题目：您在项目中使用了 LangGraph 与 Dify，对于复杂的工作流，如何解决 Agent 可能出现的逻辑偏差或死循环？

  • 参考答案要点：
    • [cite_start]状态机管理： 利用 LangGraph 等工具将“问答、自动化、浏览器操作”统一为可编排的工作流，通过显式的状态转移控制逻辑 [cite: 8, 22]。
    • [cite_start]异常归因： 建立失败案例归因机制（如检索偏差、切块问题或模型偏离），并形成修复闭环 [cite: 23]。
    • [cite_start]工具沙箱： 在受控的工具沙箱中运行 Agent 逻辑，配合提示注入防护确保流程不被非法篡改 [cite: 4, 23]。

二、 RAG 工程化与检索深度

3. 题目：简历中提到您搭建了支持“混合检索 + 重排”的 RAG 体系，请问如何优化检索的准确性与引用可信度？

  • 参考答案要点：
    • [cite_start]多路召回： 采用 Hybrid 检索（BM25 + 向量）结合 rerank 重排，提升文档召回的相关性 [cite: 4, 9]。
    • [cite_start]引用校验： 实施强制引用（citation）策略与答案置信度门控，对于低置信度结果采取拒答策略，防止模型幻觉 [cite: 4, 9]。
    • [cite_start]精细化解析： 针对 PDF/HTML 等文档进行版面分块与去噪，支持多知识域隔离，确保检索源头数据的质量 [cite: 9]。

4. 题目：对于 MCP (Model Context Protocol) 协议，您如何理解其在 Agent 工具化接入中的价值？

  • 参考答案要点：
    • [cite_start]标准化接入： 能够将内部系统以标准化的“工具”形态接入 Agent，实现本地与远程两种调用形态的复用 [cite: 2, 26]。
    • [cite_start]最小权限原则： 按“最小权限 + 可观测 + 可回放”原则封装操作，提升多 Agent 复用时的安全性 [cite: 27]。

三、 工程化保障与自动化提效

5. 题目：如何通过可观测性（Observability）体系保障企业级 LLM 应用的 SLA？

  • 参考答案要点：
    • [cite_start]全链路观测： 引入可观测性工具进行链路追踪（Trace）、指标监控（Metrics）与日志审计（Logs） [cite: 4, 12]。
    • [cite_start]成本看板： 建立按租户、模型或链路分摊的成本看板，实现 SLA 告警闭环 [cite: 12]。
    • [cite_start]工程化部署： 利用 Docker 化部署、CI/CD (GitHub Actions) 以及灰度发布与回滚机制确保线上稳定 [cite: 4, 12]。

6. 题目：Playwright 在您的 Agent 体系中除了数据采集，还承担了哪些关键任务？

  • 参考答案要点：
    • [cite_start]能力增强： 为 Agent 提供登录态管理、元素定位及表单流程回放等可控的浏览器操作能力 [cite: 13, 29]。
    • [cite_start]自动化验收： 将回归脚本接入 CI 流程，在发布前对关键路径做自动化验收，提升交付稳定性 [cite: 30]。
