Wireshark 网络封包分析技能清单

场景占位: 抓取 与 之间的流量,分析 的网络行为
阅读顺序: 扫标题 → 记住反直觉 3-5 条即可动手

1. 用 ip.addr 而非 ip.src/dst 做双向流量过滤

  • 规则: 查看某 IP 的完整会话时用 ip.addr == <TARGET_IP>,不要分别写 src 和 dst
  • 为什么: ip.addr 自动匹配源和目的地址,避免漏抓响应包;新手常只写 ip.src 导致只看到请求没响应
  • 踩坑: 写 ip.src == <IP> 只能看到该 IP 发出的包,收到的回包全部丢失
  • 例外: 明确只想看单向流量(如只看攻击源)时才用 ip.src/dst

2. 包编号 No. 不受过滤影响,用它做时序锚点

  • 规则: 记录问题时用 No. 编号而非 Time,过滤后编号不变但时间戳会跳跃
  • 为什么: 过滤器只隐藏显示,不改变原始编号;时间戳在过滤后看起来不连续容易误判丢包
  • 踩坑: 看到时间戳从 10.001s 跳到 10.500s 以为丢包,实际是中间包被过滤了

3. TCP 握手的 Seq 是累计发送字节数+1,不是包序号

  • 规则: SYN 包的 Seq 是随机初始值,后续 Seq = 初始值 + 已发送字节数
  • 为什么: Seq 用于字节流重组,不是包计数器;新手误以为 Seq 连续就是包连续
  • 踩坑: 看到 Seq 跳变 1000 以为丢包,实际是对方发了 1000 字节数据
  • 例外: SYN 包的 Seq 是随机数,不遵循累加规则

4. Len=0 的包不是空包,是控制包

  • 规则: ACK/SYN/FIN 包的 Len=0 是正常的,它们不携带应用数据
  • 为什么: TCP 控制包只改变连接状态,不传输 payload;新手误以为 Len=0 是异常
  • 踩坑: 抓到大量 Len=0 的 ACK 包以为网络有问题,实际是正常的确认包

5. 过滤器用 or 连接多条件时必须加括号

  • 规则: 写 (ip.src == <IP_A> or ip.dst == <IP_B>) and tcp.port == 443 而非不加括号
  • 为什么: Wireshark 的运算符优先级反直觉,and 优先级高于 or,不加括号会误匹配
  • 踩坑: ip.src == <IP_A> or ip.dst == <IP_B> and tcp.port == 443 实际匹配 “所有来自 IP_A 的包” + “去往 IP_B 且端口 443 的包”

6. FIN 包出现不代表连接立即关闭

  • 规则: FIN 只表示一方不再发送数据,连接仍可接收数据(半关闭状态)
  • 为什么: TCP 是全双工,一方 FIN 后另一方仍可继续发送;新手看到 FIN 就以为连接断了
  • 踩坑: 客户端发 FIN 后服务端还在传大文件,误判为异常重传

7. 时间戳格式影响问题定位效率

  • 规则: 分析延迟时改用 “Seconds Since Previous Displayed Packet” 格式
  • 为什么: 默认绝对时间戳不直观,相对时间戳能直接看出包间隔;官方文档不强调这个设置
  • 踩坑: 用绝对时间手动计算包间隔,容易算错毫秒位

8. Protocol 列显示最高层协议,不是所有协议栈

  • 规则: 看到 Protocol=HTTP 不代表没有 TCP/IP,只是显示了最上层
  • 为什么: Wireshark 自动识别协议栈并只显示最有意义的那层;新手误以为 HTTP 包不走 TCP
  • 踩坑: 过滤 tcp.port == 80 能抓到 HTTP 包,但 Protocol 列不显示 TCP

9. Info 列的内容是解析结果,不是原始数据

  • 规则: Info 显示 “GET /api/users” 是 Wireshark 解析出来的,不是包里的原始格式
  • 为什么: Info 是人类可读的摘要,实际数据在下方详情面板;新手直接复制 Info 内容去重放会失败
  • 踩坑: 看到 Info 显示 “Malformed Packet” 就以为包损坏,实际可能只是 Wireshark 不认识该协议

10. 抓包前不设过滤器,用 Display Filter 事后过滤

  • 规则: Capture Filter 在抓包时过滤(BPF 语法),Display Filter 在抓包后过滤(Wireshark 语法)
  • 为什么: Capture Filter 丢弃的包无法找回,Display Filter 只是隐藏;新手用错过滤器类型导致关键包丢失
  • 踩坑: 在 Capture Options 里写 ip.addr == <IP> 报语法错误,应该写 host <IP>

11. 同一 TCP 流的包用 Follow Stream 关联查看

  • 规则: 右键包选 “Follow → TCP Stream” 查看完整会话,不要手动过滤 ip+port
  • 为什么: Follow Stream 自动匹配四元组(src_ip, src_port, dst_ip, dst_port)并按时序排列;手动过滤容易漏掉端口复用的情况
  • 踩坑: 过滤 ip.addr == <IP> and tcp.port == 8080 抓到多个不相关的连接混在一起

12. RST 包出现代表连接异常终止,不是正常关闭

  • 规则: 看到 RST 标志说明连接被强制中断,需排查应用层或防火墙
  • 为什么: 正常关闭是四次挥手(FIN),RST 是单方面撕毁连接;新手把 RST 和 FIN 混淆
  • 踩坑: 客户端超时主动发 RST,误判为服务端拒绝连接

🔥 5 秒必记 5 条

  1. ip.addr 匹配双向流量,ip.src/dst 只匹配单向
  2. Seq 是字节累计数不是包序号,Len=0 是控制包不是空包
  3. 过滤器 or 条件必须加括号,否则优先级错误
  4. Capture Filter 抓包时过滤(BPF 语法),Display Filter 事后过滤(Wireshark 语法)
  5. RST 是异常中断,FIN 是正常关闭,别混淆
