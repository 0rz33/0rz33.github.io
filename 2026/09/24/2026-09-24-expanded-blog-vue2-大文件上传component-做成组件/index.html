前端大文件分片上传组件实现技能清单

场景占位: 上传到 ，文件用 标识，MD5 用
阅读顺序: 扫标题 → 记住反直觉 3-5 条即可动手

1. 用文件内容 MD5 做秒传判断而非文件名

  • 规则: 计算整个文件的 MD5 值作为唯一标识，上传前先发送 MD5 到服务端校验是否已存在
  • 为什么: 文件名可重复可修改，但内容相同的文件 MD5 必然相同。服务端若已有该 MD5 文件可直接返回 URL，实现秒传
  • 踩坑: 只用文件名 + 时间戳做唯一标识会导致相同文件重复上传，浪费带宽和存储
  • 例外: 小于 5MB 的文件计算 MD5 成本低，大于 500MB 的文件可考虑只计算首尾 + 采样块的 MD5 降低计算时间

2. 分片上传必须在客户端记录每个分片的上传状态

  • 规则: 为每个文件维护 {blockNum, upchunk, uploaded} 状态对象，记录总分片数、已上传分片数、已上传字节数
  • 为什么: 断点续传的核心是知道”哪些片已传哪些未传”，刷新页面或网络中断后能从断点继续而非重头开始
  • 踩坑: 只记录百分比无法精确恢复断点，必须记录具体分片索引。服务端也需要接口返回”已上传分片列表”
  • 例外: 如果服务端不支持查询已上传分片，客户端需用 localStorage 持久化状态，但要处理跨 Tab 同步问题

3. 分片大小设为 2-5MB 而非越小越好

  • 规则: 单个分片设置为 2MB-5MB（代码中 chunkSize 参数），不要设置成 512KB 或 10MB
  • 为什么: 太小会导致 HTTP 请求数暴增（1GB 文件切 512KB 需 2000 次请求），太大会导致单次失败重传代价高且进度更新不平滑
  • 踩坑: 移动端弱网环境建议 2MB，PC 端千兆网可用 5MB。CDN 有单请求体大小限制时需适配
  • 例外: 视频流媒体场景若需边传边转码，分片大小需与转码器输入块对齐（如 HLS 的 TS 分片）

4. 每个分片独立计算 MD5 用于服务端校验完整性

  • 规则: 不仅整个文件算 MD5，每个分片也要算 MD5 并在上传时附带到请求参数或 Header 中
  • 为什么: 网络传输可能损坏数据，服务端收到分片后重新计算 MD5 对比，不一致则拒绝该分片要求重传
  • 踩坑: 只校验整体文件 MD5 无法定位哪个分片损坏，会导致整个文件重传。分片 MD5 能精确定位坏片
  • 例外: 使用 HTTPS + 云厂商对象存储时，传输层已有校验和，可省略分片 MD5 降低客户端计算负担

5. 用 CancelToken 实现单文件上传的可取消而非全局中断

  • 规则: 为每个文件的上传请求绑定独立的 Axios CancelToken，存储在文件对象的 cancel 字段中
  • 为什么: 批量上传时用户可能只想取消某一个文件，全局 abort 会中断所有文件。独立 token 实现细粒度控制
  • 踩坑: 取消后必须清理该文件的状态和 DOM，否则进度条残留且无法重新上传同名文件
  • 例外: 页面卸载时需要全局取消所有上传，此时遍历 files 数组调用每个 cancel() 方法

6. 视频文件必须在客户端提取时长和封面而非依赖服务端

  • 规则: 用 <video> 元素加载文件获取 duration，用 Canvas 截取首帧作为封面，在上传前完成
  • 为什么: 服务端转码提取耗时长且消耗资源，客户端提取是免费的且能立即展示预览，提升用户体验
  • 踩坑: 必须等 loadedmetadata 事件触发才能读 duration，直接读会得到 NaN。封面截取需处理视频旋转角度（EXIF）
  • 例外: Safari 对某些编码格式支持差，可能无法提取时长，此时降级到服务端处理

7. 文件唯一标识用 uploadkey+文件属性组合 MD5 而非单一维度

  • 规则: uniqueFileName = md5(uploadkey + name + type + lastModifiedDate + size) 生成唯一 ID
  • 为什么: 同一用户可能上传同名文件的不同版本，单用文件名会冲突。组合多维度确保唯一性且可追溯
  • 踩坑: lastModifiedDate 在某些系统会被文件管理器修改，导致同一文件生成不同 ID。可考虑去掉该字段只用 size+内容 MD5
  • 例外: 如果业务要求”同名文件自动覆盖”，则只用文件名做标识

8. 批量上传时必须串行计算 MD5 避免浏览器卡死

  • 规则: 用 for 循环 + await 逐个计算文件 MD5，不要用 Promise.all 并行计算
  • 为什么: MD5 计算是 CPU 密集型操作，10 个大文件并行计算会占满所有核心导致页面假死
  • 踩坑: Web Worker 可以避免主线程卡顿，但要处理 Worker 数量控制（建议最多 2 个并行）和文件传输开销
  • 例外: 小于 10MB 的文件可以并行计算，因为耗时短不会明显影响交互

9. 上传状态用枚举值而非中文字符串

  • 规则: 定义 status: 'pending' | 'uploading' | 'success' | 'failed' | 'canceled'，显示时再映射中文
  • 为什么: 中文字符串难以做精确判断（全角半角、空格），且不利于国际化。枚举值便于 switch-case 和状态机
  • 踩坑: 直接用中文”上传中””已完成”会导致判断逻辑写成 if (status.includes('上传')) 这种不严谨的代码
  • 例外: 纯展示型项目且永远不会国际化时可以用中文，但仍建议用常量定义避免拼写错误

10. 进度计算必须基于字节数而非分片数

  • 规则: progressPercent = (uploaded / file.size) * 100，其中 uploaded 是已上传字节数累加
  • 为什么: 最后一个分片可能不足 chunkSize，用分片数计算会导致进度跳变（如 99% 直接跳 100%）
  • 踩坑: 每个分片上传成功后要累加该分片实际大小到 uploaded，不能直接 += chunkSize
  • 例外: 如果所有分片严格等大（最后一片补零），可以用分片数简化计算

11. 文件类型校验必须同时检查 MIME 和扩展名

  • 规则: 从 file.type 提取 MIME 类型，同时从 file.name 提取扩展名，两者都要在白名单中
  • 为什么: 用户可以修改文件扩展名绕过前端校验，但 MIME 类型由浏览器根据文件头判断较难伪造
  • 踩坑: file.type 在某些浏览器对非标准格式返回空字符串，此时只能依赖扩展名。服务端必须再次校验
  • 例外: 内网环境且用户可信时可以只校验扩展名简化逻辑

12. 断点续传必须先请求服务端已上传分片列表

  • 规则: 上传前调用 GET /upload/status?md5=<HASH_VALUE> 获取 uploadedChunks: [0,1,3,5]，跳过这些分片
  • 为什么: 客户端 localStorage 可能被清空或跨设备续传，服务端是唯一可信的状态源
  • 踩坑: 服务端必须持久化分片状态（Redis/数据库），且设置过期时间（如 7 天）避免垃圾数据堆积
  • 例外: 临时文件上传（如聊天图片）可以不支持断点续传，失败直接重传

13. 组件必须暴露生命周期钩子而非写死业务逻辑

  • 规则: 用 this.out('OnFileAddStart', files) 触发自定义事件，让父组件监听处理业务逻辑
  • 为什么: 上传组件是通用能力，不同业务对”上传成功后”的处理不同（跳转、刷新列表、通知等），不能耦合在组件内
  • 踩坑: 事件命名要语义化且带前缀（如 OnFile*），避免与原生事件冲突。参数要包含足够上下文（文件对象、索引）
  • 例外: Demo 或内部工具可以直接写业务逻辑在组件内快速实现

14. 多文件上传时每个文件独立维护进度而非共享一个进度条

  • 规则: v-for 遍历 files 数组，每个文件渲染独立的进度条和状态，绑定到 file.progressPercent
  • 为什么: 共享进度条无法体现单个文件状态（某个失败了用户不知道是哪个），且无法单独取消或重试
  • 踩坑: 进度条组件要绑定 :key="file.md5" 而非 index，否则删除文件时会错位
  • 例外: 批量上传几百个小文件时可以只显示总进度 + 文件计数，避免 DOM 过多卡顿

15. 上传失败必须区分可重试和不可重试错误

  • 规则: 捕获 HTTP 状态码，4xx 客户端错误（如 413 文件过大）标记为不可重试，5xx 和网络错误可重试
  • 为什么: 盲目重试会浪费带宽且永远不会成功（如文件格式不支持），明确告知用户原因才能解决问题
  • 踩坑: 网络超时要设置最大重试次数（如 3 次）和指数退避间隔（1s、2s、4s），避免无限重试
  • 例外: 关键业务（如付费上传）可以提示用户手动重试而非自动重试，避免扣费纠纷

🔥 5 秒必记 5 条

  1. 文件 MD5 做秒传，分片 MD5 做完整性校验
  2. 分片 2-5MB，状态记录到 {blockNum, upchunk, uploaded}
  3. 进度用字节数算不用分片数，避免跳变
  4. 每个文件独立 CancelToken 和进度条，不共享
  5. 断点续传先问服务端要已上传分片列表
