[expanded] [blog] vue2 大文件上传component(做成组件)

原始问题: [blog] vue2 大文件上传component(做成组件)

前端大文件分片上传组件技能点清单(Vue2)

场景占位: 上传至 , 文件标识用 , 分片索引用
阅读顺序: 扫标题 → 记住反直觉 3-5 条即可动手

1. 先算文件 MD5 再切片,阻塞式串行处理多文件

  • 规则: 每个文件必须先完整计算 MD5(秒传判断依据)再切片,多文件用 for 循环串行处理而非 Promise.all
  • 为什么: 并行计算多个大文件 MD5 会撑爆浏览器内存(FileReader 同时读取多个 GB 文件),串行虽慢但稳定;MD5 必须先算完才能判断服务端是否已存在(秒传)
  • 踩坑: 用 files.map(async) 并行处理 5 个 2GB 文件直接卡死标签页
  • 例外: 文件小于 100MB 且数量少于 3 个时可并行

2. 分片上传进度用”已上传分片数/总分片数”,不用字节累加

  • 规则: 进度条绑定 upchunk / blockNum 而非 uploaded / file.size,每个分片成功回调后 upchunk++
  • 为什么: 字节累加需要监听每个分片的 xhr.upload.onprogress,在断点续传场景下已上传分片的进度无法复现,分片计数更可靠且实现简单
  • 踩坑: 断点续传后进度条从 0 开始重新跑,用户以为上传失败重新开始
  • 例外: 需要精确到字节的实时速率显示时必须用 onprogress

3. 文件唯一标识用”上传密钥+文件元信息”的 MD5,不直接用文件内容 MD5

  • 规则: uniqueFileName = md5(uploadkey + name + type + lastModifiedDate + size),与文件内容 MD5(fileMd5)分开
  • 为什么: 文件内容 MD5 用于秒传判断(服务端去重),uniqueFileName 用于前端断点续传状态恢复(localStorage key);同一文件被不同用户上传时 fileMd5 相同但 uniqueFileName 不同,避免状态混乱
  • 踩坑: 多用户上传同一文件时断点续传状态互相覆盖,A 用户续传了 B 用户的进度

4. 视频时长和 MD5 计算必须用 await 串行,不能依赖 Promise 链式

  • 规则: 用 await getFileMd5(file).then() 而非单独 getFileMd5(file).then(),确保 fileMd5 变量在后续代码执行前已赋值
  • 为什么: 示例代码中 let fileMd5 = "" 在 await 外层声明,如果不 await 直接进入下一步,fileMd5 仍是空字符串导致秒传判断失效
  • 踩坑: 文件明明已存在服务端,前端仍然重新上传所有分片,因为 fileMd5 为空字符串跳过了秒传检查

5. 文件类型校验用 MIME type 的扩展名部分,不用 file.name 后缀

  • 规则: const ext = '.' + file.type.split('/')[1] 然后匹配白名单,不用正则提取 file.name 的 .mp4
  • 为什么: file.name 可被用户随意修改(改后缀欺骗),file.type 是浏览器根据文件头判断的 MIME 类型更可靠
  • 踩坑: 用户把 .exe 改成 .mp4 绕过前端校验上传恶意文件
  • 例外: 需要支持无扩展名文件或浏览器无法识别的自定义格式时必须结合后端二次校验

6. 分片大小固定为构造函数参数,不根据文件大小动态调整

  • 规则: this.chunkSize 在组件初始化时设定(如 5MB),所有文件用同一分片大小,最后一片用 file.size % chunkSize
  • 为什么: 动态分片(大文件用大分片)会导致断点续传时分片边界对不上,服务端合并文件时校验失败;固定分片简化状态管理
  • 踩坑: 用户上传 10GB 文件时前端自动改用 50MB 分片,断点续传时服务端期望 5MB 分片导致合并失败

7. 上传列表用 MD5 去重而非文件名,允许同名不同内容文件

  • 规则: files.findIndex(item => item.md5 === fileMd5) 判断重复,不用 item.name === file.name
  • 为什么: 用户可能上传多个同名但内容不同的文件(如不同版本的 video.mp4),用文件名去重会误杀;MD5 相同才是真正的重复文件
  • 踩坑: 用户选择新版本 final.mp4 覆盖旧版本,前端因文件名相同拒绝添加

8. 每个文件对象必须包含独立的 cancel 令牌,不共用全局取消器

  • 规则: fileblock 结构中 cancel: null 字段存储该文件的 axios CancelToken,删除文件时调用 file.cancel()
  • 为什么: 多文件并行上传时,取消单个文件不应影响其他文件;共用全局 CancelToken 会导致取消一个文件时所有上传中断
  • 踩坑: 用户删除列表中第 2 个文件,结果所有文件上传都停止

9. 视频时长获取用 video 元素 loadedmetadata 事件,不用 canplaythrough

  • 规则: 创建临时 <video> 元素,监听 loadedmetadata 事件读取 duration,不等待 canplaythrough
  • 为什么: loadedmetadata 只需加载元数据(几百 KB)即可获取时长,canplaythrough 需要缓冲足够播放数据(可能几十 MB),大文件会等很久
  • 踩坑: 获取 5GB 视频时长等待 30 秒,因为浏览器在缓冲可播放数据

10. 文件切片用 Blob.slice 而非读取到内存再分割

  • 规则: file.slice(start, end) 返回原文件的视图(不复制数据),循环生成分片数组
  • 为什么: slice 是零拷贝操作,10GB 文件切 2000 片只生成 2000 个指针;如果用 FileReader 读取再 split 会瞬间占用 10GB 内存
  • 踩坑: 切片 8GB 文件时浏览器标签页崩溃,因为尝试把整个文件读入 ArrayBuffer

11. 上传状态用枚举字符串而非数字,方便调试和日志

  • 规则: status: '准备' | '上传中' | '暂停' | '完成' | '失败',不用 status: 0 | 1 | 2 | 3 | 4
  • 为什么: 控制台和日志直接显示 "上传中" 比 1 可读性强,排查问题时不需要查状态码映射表
  • 踩坑: 生产环境日志显示 status: 2,3 个月后没人记得 2 代表什么状态

12. 进度条颜色用函数返回而非固定值,根据状态动态变化

  • 规则: :color="customColor" 绑定方法,根据 status 返回不同颜色(上传中蓝色/完成绿色/失败红色)
  • 为什么: 用户需要快速识别哪些文件上传失败需要重试,颜色是最直观的视觉反馈
  • 例外: 严格遵循设计规范要求统一进度条颜色时不适用

13. 文件添加事件用 out() 方法触发父组件回调,不用 $emit

  • 规则: this.out('OnFileAddStart', files) 触发自定义事件,父组件通过配置对象传入回调函数
  • 为什么: 组件用 Vue.component 全局注册而非单文件组件,out() 是封装的事件总线方法,比 $emit 更灵活(支持非父子组件通信)
  • 踩坑: 用 this.$emit('OnFileAddStart') 发现父组件收不到事件,因为不是标准的父子组件关系

14. 多文件上传用 v-for 渲染独立进度条,不用单一进度条显示总进度

  • 规则: v-for="(file, index) in files" 为每个文件渲染独立的进度条和操作按钮
  • 为什么: 用户需要知道每个文件的具体进度和状态,单一总进度条无法体现哪个文件失败需要重试,也无法单独取消某个文件
  • 踩坑: 10 个文件上传时只显示总进度 60%,用户不知道是哪个文件卡住了

15. 文件 URL 和时长用 v-model 双向绑定输入框,支持手动修改

  • 规则: <el-input v-model="file.url"> 和 <el-input v-model="file.playtime"> 允许用户编辑
  • 为什么: 自动获取的视频时长可能不准确(编码问题),URL 可能需要手动调整路径或添加 CDN 前缀,给用户修正机会
  • 例外: 严格的数据一致性要求(如金融场景)禁止手动修改时不适用

🔥 5 秒必记 5 条

  1. 先算 MD5 再切片,多文件串行处理防内存爆
  2. 进度用分片计数(upchunk/blockNum)不用字节累加,断点续传才准确
  3. 文件内容 MD5(秒传)和唯一标识 MD5(断点续传)必须分开
  4. 分片大小固定不动态调整,否则断点续传边界对不上
  5. 每个文件独立 cancel 令牌,删除单个不影响其他

决策速查(遇到 X 想 Y)

遇到 想
多文件同时上传卡死 改串行处理,for 循环 await
断点续传后进度归零 检查是否用字节累加而非分片计数
秒传不生效 确认 fileMd5 是否在 await 后才赋值
